## 0. Propósito
Identificar las condiciones que deberá cumplir el proyecto y establecer alternativas técnicas o metodológicas que puedan compararse en el análisis de viabilidad.

## 1. Requisitos o condiciones
Se trata de cosas que deben verificarse y cumplirse.
* Implementación de sensores con buena resolución.
* Implementación de motores con suficiente fuerza.
* Método de control estable para el sistema propuesto.
* Modelo matemático del robot delta fiel al construido.
* Dinámica del modelo del robot delta.

## 2. Restricciones
Son los límites que no pueden modificarse libremente.
* Uso de FPGA como procesador para aplicar el método de control.
* Arquitectura de un robot paralelo tipo delta.
* Necesidad de una etapa de potencia para el control de los motores.

## 3. Supuestos
Afirmaciones provisionales que faltan por comprobar.
* Un robot delta sigue una dinámica no lineal.
* Es posible modelar matemáticamente un robot paralelo tipo delta.
* Los laboratorios a los que se tiene acceso tienen las herramientas necesarias para llevar a cabo el proyecto.
* El procesamiento síncrono y paralelo en la FPGA eliminará el cuello de botella de muestreo de los microcontroladores y reducirá el error de seguimiento en movimientos ultrarrápidos.
* Es posible describir e implementar la cinemática inversa y lazos de control dentro de los recursos de la tarjeta FPGA elegida.

## 4. Alternativas

### Microcontrolador secuencial como dispositivo de control.
* Descripción general: Controlar el robot delta empleando una tarjeta de procesamiento digital de propósito general (microcontrolador de alto rendimiento o DSP) mediante ejecución de código secuencial tradicional.
* Funcionamiento o método: El microcontrolador muestrea de forma secuencial los sensores de posición, resuelve las ecuaciones cinemáticas inversas punto por punto y envía progresivamente las señales de mando a los tres motores del robot.
* Recursos necesarios: Microcontrolador de alta velocidad con capacidades de alta velocidad.
* Ventajas esperadas: Simplicidad de programación y facilidad de consulta de materiales relacionados en internet.
* Limitaciones: Efecto de cuello de botella que entorpece las mediciones y el control a altas velocidades.
* Riesgos o incertidumbres: Pérdidas de precisión y posible desviación a altas velocidades.
* Información pendiente: Cantidad de muestreos posibles para algún microcontrolador propuesto.

### Distribución de tareas entre distintos microcontroladores.
* Descripción general: Diseñar distintos módulos especializados basados en microcontroladores para realizar tareas específicas, emulando el funcionamiento de un FPGA y repartiendo los cálculos entre los módulos, cada uno funcionando en paralelo.
* Funcionamiento o método: Se diseñarían distintos módulos especializados centrados en secciones específicas de los cálculos del método de control y en la adquisición y el envío de datos.
* Recursos necesarios: Múltiples microcontroladores así como electrónica provisional para interconectarlos.
* Ventajas esperadas: Simplicidad de programación manteniendo una buena velocidad de respuesta.
* Limitaciones: Velocidad del protocolo de comunicación entre microcontroladores empleado.
* Riesgos o incertidumbres: Consumo mayor de corriente eléctrica así como necesidad de más electrónica para la construcción de los sistemas mínimos de cada microcontrolador.
* Información pendiente: Microcontrolador a implementar, protocolo de comunicación entre microcontroladores, división de tareas entre los microcontroladores.


## 5. Criterios Preliminares de Comparación
Parámetro que se utilizará para evaluar y comparar las alternativas en el análisis de viabilidad.
* Determinismo del sistema: Misma respuesta ante las mismas entradas.
* Velocidad máxima: Velocidad máxima que el modelo propuesto puede alcanzar manteniendo su precisión sin arrastrar ningún error.
* Bloques lógicos requeridos: La cantidad de Configurable Logic Blocks (CLB) requeridos por la FPGA para ejecutar el programa.
* Escalabilidad del software: Probar con robots paralelos tipo delta de distintas dimensiones buscando ajustar la menor cantidad de parámetros posibles para hacerlo compatible (dimensiones, propiedades de los motores)
* Sintonización adecuada: Dependiendo del método de control empleado, buscar parámetros balanceados para las aplicaciones buscadas, como un tiempo de subida rápido sin obtener un sobrepaso perjudicial para la aplicación del robot.
* Robustes: Tolerancia a la variación de parámetros como la carga aplicada sobre el efector, incrementos o disminuciones de velocidad, condiciones ambientales, entre otras.
